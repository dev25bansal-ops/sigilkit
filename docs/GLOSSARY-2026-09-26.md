## 0. 结论摘要

| 指标 | 数值 |
|---|---|
| 收录标准术语 | **118** 条（§2） |
| 发现命名不一致 | **31** 组（§3），其中**必须统一 10** 组（§4） |
| 发现术语误用/技术错误 | **9** 条（§5），其中 **4 条为技术误导**（会让读者对系统行为产生错误认知） |
| 示例地址核对 | 8 处 `0x`+40 十六进制串，**1 处无效**（长度 38，非 42） |
| 文档函数名核对 | 11 个被文档引用的 SDK/合约函数，**3 个在代码中不存在** |

**最重要的三条发现**（详见 §5.1 / §3-I1 / §3-I2）：

1. **`0x1111111111111111111111111111111111111111` 只有 38 个 hex 字符，不是合法地址**（应为 40）。
   它在 `packages/core/README.md:98` 被当作"你允许的 ERC-20"写进可运行示例，而 README 同一段
   声称"every value is a real address/hash"。这是**唯一一条会被读者直接复制走的错误**。
2. **窗口语义在代码与知识库之间正面对撞**：代码三处显式写 `fixed (tumbling) window`，
   `vault/` 三处写 `rolling window` / `sliding-window`。二者不是同一种窗口（tumbling 允许
   跨窗 2× 超限，sliding 不会），选错会导致对 INV-1 的错误理解。
3. **`ERC-7702` 在 3 处被当作规范名使用**。7702 是 **EIP**（最终标准，2025-05-07 Pectra 上线），
   不是 ERC；仓库自己的代码与 `lib/forge-std` 一律写 `EIP-7702`。

## 3. 命名不一致清单（31 组）

严重级定义：
- **P0 阻断** = 会导致读者对系统行为产生**错误**认知，或复制示例直接失败
- **P1 重要** = 跨文件搜索/工具链断裂，或明显影响可读性
- **P2 可接受** = 风格差异，不影响理解

### P0 阻断级（5 组）

#### I1 · 窗口语义冲突：`tumbling`（代码）vs `rolling/sliding`（vault）⚠ 最高优先

| 位置 | 原文 | 计数 |
|---|---|---|
| `contracts/src/SpendPolicy.sol:5-7` | `fixed-window (tumbling) spend caps` / `INV-1 (tumbling window)` | 代码基准 |
| `contracts/src/SessionKeyManager.sol:51,53` | `fixed (tumbling) window length` / `per fixed (tumbling) window` | 代码基准 |
| `contracts/src/SessionKey7579Module.sol:23,72,74` | `fixed-window (tumbling) rate limits` | 代码基准 |
| `vault/Agent Architecture.md:63` | `rolling reset when now - windowStart >= windowSeconds` | 1 |
| `vault/Agent Architecture.md:69` | `per-action + rolling window + Merkle` | 1 |
| `vault/Component 4 — Agent Session-Key Manager.md:13` | `rolling window reset when now - windowStart >= windowSeconds` | 1 |
| `vault/README.md:11` | `why E15 sliding-window` | 1 |
| `docs/STATUS.md:53` | `E15 (sliding-window damping) deliberately not built` | 1 |

**为什么是 P0**：这不是措辞问题。tumbling 窗口在跨窗时可累计到 **2× perWindowCap**
（`README.md:183` 明文承认）；sliding 窗口不会。一个按 vault 描述做容量规划的运维者
会算出偏乐观一倍的额度。`vault/Agent Architecture.md:63` 的算法描述（`now - windowStart >= windowSeconds`
则重置）本身**就是 tumbling 的实现**，只是名字叫错了 —— 属于纯命名错误，但后果是概念错误。

**判定**：**必须统一**。建议 vault 全部改为 `fixed (tumbling) window`；`sliding-window` 保留但明确标注
为"E15，未实现"，并加一句"与 tumbling 不同"。

### P1 重要级（12 组）

#### I6 · `ERC-7579` vs `EIP-7579`（6 处混用）

`ERC-7579` 出现于 33 个文件（含 `README.md`、`SECURITY.md`、`docs/WHITEPAPER-v2.1.md`）；
`EIP-7579` 出现于 6 个文件：`docs/VAULT-AUDIT-2026-09-26.md`、`docs/PLAN-30-DAYS-*.md:23`、
`docs/Issues-Catalog-2026-09-21-Agent-Review.md:435`、`docs/ECOSYSTEM-RESEARCH-2026-09-23.md:30`
（同文件同行内混用）、`docs/COMPLIANCE-2026-09-26.md:621`、`docs/ARCH-CONTRACTS-2026-09-26.md:522`。

**判定**：**必须统一为 `ERC-7579`**。理由：7579 是 ERC 命名空间（`eips.ethereum.org/EIPS/eip-7579`
虽托管在 EIP 仓库，但编号归属 ERC 系列），且仓库主流写法已是 ERC-7579。6 处少数派应改。
注意 `docs/ECOSYSTEM-RESEARCH-2026-09-23.md:30` 同一段落内 `ERC-7579` 与 `EIP-7579` 并存，
是最明显的自相矛盾点。

#### I7 · `delegate` 家族：designator / designation / delegate / delegator 混用

| 词 | 含义 | 使用情况 |
|---|---|---|
| `designator` | EOA 账户上被安装的码（`0xef0100‖addr`） | 代码用（`eip7702.ts:348 DELEGATION_PREFIX`、`coinbase.ts:141`）；文档 `docs/DEPLOY-OPS-2026-09-26.md` 大量用（约 10 处） |

| `delegate`（动词） | 授权动作 | 通用 |
| `delegator` | 合约名 `SigilKitDelegator` | 代码 + README |
| `delegated EOA` | 已授权的 EOA | `docs/DOC-AUDIT-CONTRACTS-2026-09-26.md:35` |

**判定**：**P1，需定义**。`designator` / `designation` 指的是**同一个链上码**，
必须择一。EIP-7702 规范本身用 "delegation designator"，故建议统一为 **delegation designator**。

#### I8 · `tumbling window` 相关：INV-1 的 2× 溢出只在 2 处说明

`README.md:183` 与 `docs/WHITEPAPER-v2.1.md:12` 写 `fixed-window (tumbling)`；
但"Up to ~2× perWindowCap may cross a window boundary"这句**只在 `README.md:183`**。
`SECURITY.md` 有 5 处窗口相关表述但无一处解释 tumbling 语义。

**判定**：**P1**。tumbling 的 2× 溢出是安全模型的一部分，不是实现细节，
应进 `SECURITY.md`（安全语义）与 §2 术语表。

## 5. 误用 / 错误的技术术语清单

> 与 §3 的区别：§3 是"两个名字指同一个东西"；这里是**用错了标准、编号或事实**。

### 5.1 🔴 `0x1111…1111` 不是合法地址（可复制的技术错误）

`packages/core/README.md:98`：

```ts
const token = "0x1111111111111111111111111111111111111111";        // the ERC-20 you allow
```

hex 字符数 = **38**（`1` × 38），合法地址需要 **40** 个 hex 字符 = 42 字符总长。
同一段代码上方 `packages/core/README.md:81-82` 声称：

> "Every identifier is declared, **every value is a real address/hash**, and the whole flow
> is the one the SDK actually supports."

这句话为**错误示例**背书。该串在 5 个 indexer 测试中也被使用
（`packages/indexer/test/{indexer,event-parsing,migrate,reorg-cache,query-plan}.test.ts`），
说明它是测试占位符，被误抄进面向用户的 README。

**正确写法**：`0x1111111111111111111111111111111111111111`（40 个 `1`）或直接用
Anvil 默认地址 `0x5FbDB2315678afecb367f032d93F642f64180aa3`（同文件 97 行用的就是这个）。

**判定：最高优先修复。** 这是本次审计中**唯一一条会被读者原样复制走**的错误。
