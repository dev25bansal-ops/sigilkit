# RFC 9116 §2.5.5 Encryption. NO `Encryption:` FIELD IS PRESENT YET — DO NOT ADD ONE
# UNTIL A REAL KEY EXISTS. An `Encryption:` value must be a resolvable OpenPGP key
# identifier; publishing a fingerprint that resolves to no key is worse than publishing
# nothing, because a reporter who encrypts to an unresolvable key silently loses the
# report. This omission is deliberate and must be closed by the steps below, not by
# pasting a placeholder.
#
# TO CLOSE THIS (maintainer, ~5 minutes, no private key leaves your machine):
#   1. Create a key dedicated to this purpose (do NOT reuse a personal key):
#        gpg --full-generate-key --expert
#        Key type: RSA and RSA  # Key strength: 4096
#        Name/email:          SigilKit Security <dev25bansal@gmail.com>
#        No passphrase is acceptable here — the private key must be usable unattended.
#   2. Publish the PUBLIC key where the fingerprint resolves, e.g.
#        gpg --keyserver hkps://keys.openpgp.org --send-keys <FPR>
#        gpg --keyserver hkps://keyserver.ubuntu.com --send-keys <FPR>
#   3. Verify it actually resolves BEFORE editing this file:
#        gpg --keyserver hkps://keys.openpgp.org --recv-keys <FPR>
#   4. Add the line below (uncomment), then re-run `npm run check:docs`:
